# ggethos refactor roadmap (draft)

Goal: reduce magic by making input modes explicit, separating data preparation
from plotting, and surfacing grouping/alignment as first-class concepts.

## Phase 0: contract + tests (no behavior change)

- Publish a behavior contract (inputs, grouping, alignment).
- Add a test matrix scaffold (unit + snapshot) keyed to the contract.
- Mark legacy behavior as "inferred" and warn in ambiguous cases.
- Expand docs with hand-holding examples that show expected shapes, tables, and
  computed segments (include small data prints alongside plots).

Deliverables:
- `docs/behavior-contract.md`
- Test file skeletons for each mode.

## Phase 1: explicit data-prep helpers (new API)

Introduce mode-specific helpers that return segment data. These should be
exported and documented. `geom_ethogram()` should call these helpers internally
to avoid diverging logic.

Proposed functions:
- `compute_intervals(data, x, xend, y, behaviour = NULL, group = NULL, ...)`
- `compute_samples(data, x, y, behaviour = NULL, group = NULL,
  interval = NULL, interval_mode = c("explicit","guess"), ...)`
- `compute_implied(data, y, behaviour = NULL, group = NULL, ...)`
- `align_ethogram(data, by, mode = c("zero","time","midnight"))`

Notes:
- All helpers return a data frame with `x`, `xend`, `y`, `yend`, `PANEL`, and
  relevant aesthetics (`colour`, `group`) preserved.
- Helpers should validate grouping and fail loudly when ambiguous.

## Phase 2: `setup_data()` and `geom_ethogram()` dispatch

Implement a single `compute_ethogram()` that dispatches to the helpers based
on available columns and user-specified overrides.

Decision order:
1) If `x` + `xend` present => ranges.
2) Else if `x` present => samples (requires interval or guess).
3) Else => implied order.

`geom_ethogram()` behavior:
- Accept a new `mode` argument (`"auto"`, `"ranges"`, `"samples"`, `"order"`).
- Accept new alignment helpers (`align = FALSE` or `align_by =`).
- Call `compute_ethogram()` and pass segments to `GeomSegment`.

## Phase 3: alignment grammar layer

Allow pipeline usage:

```
df %>%
  ethogram_from_samples(x = datetime, y = pair_id, behaviour = state, group = animal_run_id,
                        interval = "5 secs") %>%
  align_ethogram(by = pair_id, mode = "time") %>%
  ggplot(aes(x = x, xend = xend, y = y, yend = yend, colour = behaviour)) +
  geom_ethogram(stat = "identity")
```

Implementation detail:
- `align_ethogram()` should be independent of run collapsing and accept explicit
  `by` keys, matching the user story.

## Phase 4: cleanup + deprecations

- Deprecate ambiguous legacy behavior (e.g., implicit grouping).
- Update vignettes and README to show explicit pipeline usage.
- Add diagnostics for mixed intervals, overlapping behaviors, and NA scales.
- Add a test that verifies the recomputation warning when `stat != "identity"`
  is used on computed ethogram data.
- Add NA-handling tests for each compute mode (implied, samples, intervals),
  covering NAs in `behaviour` vs NAs in `x`/`xend` (especially datetime).
- Add a "red-team" test suite that intentionally breaks assumptions
  (duplicated labels, mixed sampling, mis-grouped facets, overlapping intervals).
  - Implemented initial scripts in `tests/antagonist/ggethos_attack.R` and
    `tests/antagonist/ggethos_attack2.R`, `tests/antagonist/ggethos_attack3.R`
    `tests/antagonist/ggethos_attack4.R`
    `tests/antagonist/ggethos_attack5.R`
    `tests/antagonist/ggethos_attack6.R`
    to document current failure/silent-wrong behaviors and provide repros for
    future hardening.
  - Added a single combined entrypoint at `tests/antagonist/ggethos_attack_all.R`
    so all cases can be run from one script.
  - Added a small fixture list in `data/antagonist_cases.rda` generated by
    `data-raw/antagonist_data.R` for documentation and future tests.

## Risks + mitigations

- Breaking changes: mitigate with warnings + `mode="auto"` default.
- User confusion: solve via explicit docs + vignettes + helper examples.
- Regression: lock down with unit tests per mode and a small snapshot set.

## Performance notes (baseline, local runs)

- `compute_samples()` on 1e6 rows (single group) ~80s elapsed.
- `compute_samples()` on 5e5 rows with 5k groups ~42s elapsed.
- `compute_implied()` on 1e6 rows ~83s elapsed.
- Bottlenecks appear to be run detection (`vec_identify_runs`) + grouped summarise on large vectors.
